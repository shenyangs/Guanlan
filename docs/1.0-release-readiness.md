# Guanlan 1.0 发布准备清单

本文件定义 `1.0.0` 的准入条件。它不是发布日期承诺；只有全部必须项完成并留有可复核证据时，才进入 1.0 发布。

## 1.0 的稳定承诺

- CLI 的一级命令、已公开的 `--format json` 核心字段、MCP 工具名与 `agent_plan_v2` 决策契约，在 1.x 内保持向后兼容；确需调整时先保留兼容字段并在 changelog 标明迁移期。
- 信源路由是可演进的：允许增减站点与调权，但不得把安全、官方、时间或 `--site` 等明确约束静默放宽。
- `read` 的页面正文引用边界、`context_only`、截断与 browser-assisted 标记保持可机器判断。
- 默认保持只读、低扰和明源；任何账号、Cookie、私有页或写操作仍须单独授权。

## 必须完成

- [ ] 冻结 1.0 CLI/MCP 公开面：列出稳定命令、JSON schema 与废弃项，并为每项建立兼容性回归。
- [ ] 对核心链路建立跨版本安装验证：uv、pipx、Homebrew 和从零配置的 MCP，均安装并显示同一版本与可执行路径。
- [ ] 通过完整发布门禁：静态检查、全量测试、路由正/负/近失样例、质量/可靠性/性能检查、构建和隔离安装 smoke。
- [ ] 对搜索、热榜、正文读取、Agent 路由和至少一个结构化垂直入口做真实公共端到端 smoke，并记录证据边界。
- [ ] 连续观察信源漂移：关键原生源和高风险路由在不少于两个独立检查周期内无持续失败或未解释的质量退化。
- [ ] 处理发布自动化缺口：PyPI、Homebrew tap 和官网部署均可在一次发布链路中同步；外部凭据失效必须在 tag 前暴露并阻断发布。
- [ ] 官网、README、安装文档、`SECURITY.md`、changelog 和发布说明统一为 `1.0.0`，并提供从 0.10.x 升级的迁移说明。

## 发布演练

在不打正式 tag 的预演中，执行以下流程并保存输出：

1. 以干净工作树运行 `scripts/release_gate.sh`。
2. 构建 wheel/sdist，并在隔离环境中安装，检查 `guanlan version`、`capabilities`、`doctor --install-check`、搜索、读取和热榜。
3. 验证 tag 触发的 PyPI Trusted Publisher、Homebrew formula 更新和官网部署；用公网分发端而非本地源码确认版本。
4. 对照 0.10.x 的兼容性夹具运行 CLI/MCP JSON 契约测试；任何破坏性差异必须有明确的迁移或兼容层。

## 当前已知收口项（2026-08-30）

- 0.10.10 的信源扩展已经补充标准、学术、开发者与告警入口，并增加回归覆盖；还需要在发布后继续观察真实上游的稳定性。
- 现有 tag 发布工作流曾因 Homebrew tap 的写入凭据失效而失败。1.0 前必须修复或改造为可验证的同步路径，不能靠事后人工补齐作为常规机制。
- 线上官网源站仍需随每个版本实际部署并从公开域名复核，不能只更新仓库内的 `website/index.html`。
