# Guanlan v0.9.0 Evidence Provenance Kernel 施工与发布方案

状态：发布前门禁已通过，等待分发表面同步

基线：v0.8.5（`1047 passed, 1 skipped`；release gate 14/14 通过）

原则：只做增量能力；默认行为、结果顺序和现有字段不变；任何硬门禁失败都禁止发布。

## 目标与边界

v0.9.0 只交付一条可验证的证据来源主链：公开页面经过安全读取后形成稳定的
`SourceIdentity -> DocumentSnapshot -> Passage -> ClaimCandidate -> EvidenceLink`，并以新增的
`evidence_bundle_v1` 随研究结果返回。Archive 保存同一 URL 的历史快照，同时维持 0.8.5 的
“当前文档”投影和查询行为。MCP 默认暴露面不变，仅提供显式启用的 compact profile。

本版本不把下列能力承诺为稳定接口：通用事实判定、自动支持/反驳裁决、完整 ResearchCase、
PDF/表格精确取证、claim 级 Watch、主动重排 Evidence Mixer、MCP Tasks/Resources。保守抽取不能
确认关系时只标记 `mentions` 或 `unclear`，不标记 `supports`。

## 硬门禁

1. 0.8.5 的确定性 release gate 全部通过；既有测试通过数不得下降，失败数必须为 0。
2. Search/Research 的候选结果、顺序、默认 limit、read_top 和 Evidence Mixer 模式不变。
3. 现有 JSON 字段只增不删、不改名、不缩窄类型；MCP full profile 的工具集合完全不变。
4. Archive v1 数据库可原地、幂等迁移；旧记录可读；当前文档投影与 FTS/语义搜索结果不退化；
   新内容不覆盖历史快照。
5. Public URL 策略覆盖 scheme、凭据、IPv4/IPv6、DNS、跳转和重绑定边界；显式配置的本地端点
   使用独立策略，不被公网策略误伤。
6. 新增契约具有单元、迁移、负向、安全、结构和性能测试；无网络的确定性测试可复现。
7. 构建、安装 smoke、版本同步检查全部通过；正式发布在干净临时 worktree 中执行。
8. GitHub main/tag、PyPI、Homebrew tap、官网和本地安装必须同版；任一表面未同步都不称为完成。

## 实施顺序与止损点

1. 先建立纯数据契约和 Archive v2；若迁移、现有查询或 FTS 发生任何退化，停止后续接线。
2. 再把 bundle 接入 research，采用 shadow/additive 路径；逐项比较接入前后的结果及顺序。
3. 然后收紧结构边界和公网 URL 安全策略；本地/自托管端点通过单独策略保持兼容。
4. 最后增加 MCP compact profile；默认 full profile 继续作为兼容基准。
5. 先跑定向测试，再跑完整 release gate。只有干净 worktree 的完整结果通过，才修改版本并发布。

## 回滚策略

- Schema：保留 `documents` 当前投影；v2 新表为追加式，0.8.5 仍可读取原表。代码回滚不要求删表。
- Research：`evidence_bundle_v1` 是可忽略的新字段，可单独撤下，不影响既有字段和排序。
- URL Policy：公网与配置端点分层；若兼容性样例失败，只回滚对应入口接线，不放宽全局策略。
- MCP：compact 为显式 opt-in；删除 profile 选择即可恢复 0.8.5 默认表面。
- Release：门禁失败时不打 tag、不上传 PyPI、不更新 Homebrew/官网；已生成的本地构建物不算上线。

EP-01 至 EP-09 的验收证据全部落地且 release gate 全绿；随后 EP-10 的 GitHub、PyPI、Homebrew、
官网与本地安装版本均为 0.9.0，并完成规定 smoke。否则目标保持未完成，明确报告阻断项，不发布。
